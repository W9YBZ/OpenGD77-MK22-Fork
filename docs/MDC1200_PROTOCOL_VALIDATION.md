# MDC1200 independent protocol / encoder lab

## Scope and acceptance boundary

User-confirmed Tone35Fix continuous PTT and receiver-audible Beep remain the
radio baseline. The user additionally reports other use/functions are normal,
but cannot currently measure received audio. Do not turn this general report
into specific DMR/TOT/CPS or instrument measurements. Those items retain their
existing evidence limits.

This stage is host-only protocol research, a pure encoder and independent
vectors/tests. No firmware file, settings ABI, menu choice, TX backend, native
project, calibration or radio data is changed. MDC N/A remains unavailable.
The old unreliable OpenGD77 MDC encoder/modulator is historical context only;
its outputs and the archived experiment's vectors are not correctness oracles.

## Pinned primary sources

- [Matthew Kaufman's encoder/decoder](https://github.com/atmatthewat/mdc-encode-decode/tree/45fc9095fbde8bf6a6988c7dc0de64a4ec0ffe12),
  GPL-2.0-only, commit `45fc9095fbde8bf6a6988c7dc0de64a4ec0ffe12`.
  A standalone software modem independent of the old OpenGD77 implementation.
- [SDRTrunk MDCMessage](https://github.com/DSheirer/sdrtrunk/blob/02c62d012fe88ea581f05c6082af12ca7adf65dc/src/main/java/io/github/dsheirer/module/decode/mdc1200/MDCMessage.java)
  and its MessageProcessor at `02c62d012fe88ea581f05c6082af12ca7adf65dc`,
  GPL-3.0-or-later: separate field/event interpretation and interleave audit.
  `isValid()` contains a CRC TODO, so it cannot serve as a CRC integrity oracle.
- [EAS Station's protocol description](https://github.com/KR8MER/eas-station/blob/main/docs/reference/protocols/MDC1200.md)
  provides a conflicting post preset `00/80`. It is not used as a golden source.

The source lock records nine external files by pinned URL and SHA256. Reference
files stay under ignored `artifacts/`; fresh downloads must match before tests.
Host lab/tests are explicitly GPL-2.0-only because the algorithm audit consults
that reference. They are not linked with the noncommercial-licensed firmware;
combined redistribution/license compatibility is not claimed. SDRTrunk source
is audited separately and not incorporated into the host binary.

## Candidate layer rules — software evidence, not RF certification

| Layer | Reference-derived rule |
| --- | --- |
| Logical info bytes | op, arg, ID high, ID low, CRC low, CRC high, zero tail |
| CRC | init 0; reflected polynomial 0x8408 (normal 0x1021); xorout FFFF; first 4 bytes only |
| Systematic FEC | seven info bytes, then seven parity bytes; zero-state K=7, taps 0/2/5/6, input LSB-first per byte |
| Interleave | input bit n maps to `(n % 7)*16+n/7`; emitted bytes MSB-first |
| Reference leader | seven 55 bytes, then sync 07 09 2A 44 6F |
| Differential tone decisions | changed logical bit -> 1800 Hz, same -> 1200 Hz; previous bit starts 0; original modem seeds the first acquisition symbol at 1800 Hz |
| Logical frame | 26 bytes / 208 symbols, nominal 173.333 ms at 1200 symbols/s; no RF settling included |

Preamble length/first-symbol seeding above describe this pinned software profile,
not a claim that every commercial radio requires that exact leader length.

POST-ID semantics remain provisional: `01/00` makes SDRTrunk's ANI flag true and
EOT flag true; `01/80` is the BOT control. The conflicting `00/80` must be retained
as a counterexample in the semantic audit. External decoding of raw op/arg/ID
alone does not prove the receiving radio considers it a POST-ID event. A known
good RF capture/commercial receiver remains necessary to close that gap.

## Independent vectors generated before the new encoder

`tests/mdc1200/generate_vectors.py` compiles only the pristine pinned external
encoder and decoder adapters, not the new encoder. Frozen goldens include three
candidate POST IDs (0001/1234/FFFF), three BOT controls, and a conflicting-preset
control. They contain original CRC prefix states, info bytes, inverse-mapped
FEC block, full logical frame and tone states observed from the original modem.
The FEC intermediate is recovered by the audited external decoder geometry;
it is not generated by the implementation under test.

```sh
python3 host/mdc1200/fetch_references.py --out artifacts/mdc1200-protocol/references
python3 tests/mdc1200/generate_vectors.py \
  --references artifacts/mdc1200-protocol/references \
  --out artifacts/mdc1200-protocol/regenerated-vectors.json
cmp tests/mdc1200/golden_vectors.json artifacts/mdc1200-protocol/regenerated-vectors.json
```

## Implementation / tests to complete in this stage

Implement a fixed-size hardware-independent encoder under `host/mdc1200`, then
compare every intermediate with the external goldens. Check random packets/CRC,
bounds/null/ID-zero behavior, external block decoder CRC/FEC acceptance and
negative CRC/bit mutations. A test-only ideal PCM fixture may exercise the
external sample decoder; that would not constitute RF modulation or a captured
radio signal. Source-level SDRTrunk flag auditing is distinct from running its
full receiver. Record actual test outcomes after execution.

## RF and firmware boundary

RF encoder/modulation integration, independent off-air POST event/ID/CRC decode,
measured clock/jitter/deviation and commercial compatibility are **Not Run**.
No RF sender is implemented or enabled in this phase. The current 1 ms PIT is
not suitable for directly scheduling 833.333 us symbols. A future backend must
prove the physical RF input path and timing separately; this phase makes no
assumption that the successful PTT Beep generator supplies phase-continuous MDC.
